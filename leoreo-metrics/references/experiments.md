# 실험 설계 부록 — A/B 테스트와 대안

> 통계 수치는 관례적 기준(유의수준 5%, 검정력 80%)을 따릅니다. 리스크가 큰 결정이면 기준을 더 엄격하게 잡습니다.

## 1. 시작 전에 계산합니다

실험을 켜기 전에 세 가지를 정합니다. 정하지 않고 시작한 실험은 나중에 원하는 결론에 맞춰 해석됩니다.

1. **현재 전환율** — 대조군의 기준값
2. **최소 검출 효과(MDE)** — "이 정도는 움직여야 의미 있다"는 최소 변화폭. 사업적으로 정합니다. 전환율 2%를 2.02%로 올리는 건 감지해도 쓸모가 없습니다.
3. **필요 표본 수** — 위 둘에서 나옵니다

### 필요 표본 수 어림표 (그룹당, 유의수준 5% / 검정력 80%)

| 현재 전환율 | +10% 상대 개선 감지 | +20% | +50% |
|---|---|---|---|
| 1% | 약 155,000명 | 약 40,000명 | 약 7,000명 |
| 5% | 약 30,000명 | 약 7,500명 | 약 1,400명 |
| 10% | 약 14,500명 | 약 3,600명 | 약 650명 |
| 20% | 약 6,300명 | 약 1,600명 | 약 290명 |

읽는 법입니다. **작은 개선을 감지하려면 표본이 급격히 커집니다.** 전환율 5%에서 10% 상대 개선(5%→5.5%)을 보려면 그룹당 3만 명이 필요합니다. 하루 방문자가 500명이면 두 그룹을 채우는 데 120일이 걸립니다 — 그 실험은 하지 않는 게 맞습니다.

계산해 보고 기간이 비현실적이면 선택지는 셋입니다. 더 큰 변화를 시도하거나(MDE를 키움), 퍼널 위쪽의 트래픽이 많은 구간에서 실험하거나, A/B를 포기하고 4절의 대안으로 갑니다.

## 2. 돌리는 동안의 규칙

- **기간을 미리 못 박고 중간에 멈추지 않습니다.** 유의미해질 때까지 매일 들여다보다 멈추는 것(peeking)이 가장 흔한 실수입니다. 매일 확인하고 유의미해지면 멈추는 방식은 거짓 양성률을 5%에서 20~30%까지 올립니다. 미리 정한 표본에 도달할 때까지 결론을 내리지 않습니다.
- **최소 한 주 단위로 돌립니다.** 요일마다 사용자 구성이 다릅니다. 화요일에 켜서 목요일에 끄면 주말 사용자가 빠집니다.
- **한 번에 하나만 바꿉니다.** 버튼 색과 문구와 위치를 같이 바꾸면 무엇이 효과를 냈는지 알 수 없습니다.
- **노출(exposure) 이벤트를 기록합니다.** "실험군에 배정됨"이 아니라 "실험 화면을 실제로 봄"을 기준으로 분석해야 정확합니다.
- **배정은 사용자 단위로 고정합니다.** 세션 단위로 배정하면 같은 사람이 두 버전을 오가며 결과가 오염됩니다.

## 3. 가드레일 지표

목표 지표만 보면 이겼는데 사업은 나빠지는 일이 생깁니다. 실험마다 아래를 함께 봅니다.

| 목표 지표 | 반드시 같이 볼 가드레일 |
|---|---|
| 결제 전환율 | 환불률, 첫 달 이탈률, 고객문의 건수 |
| 가입 전환율 | 온보딩 완료율, D7 잔존 |
| 클릭률·체류시간 | 핵심 행동 완료율(허영 지표 상승만일 수 있음) |
| 무엇이든 | 응답속도(p95), 오류율 |

가드레일이 나빠졌으면 이긴 게 아닙니다. 특히 **결제 전환이 오르고 환불률이 같이 오르면** 잘못된 기대를 심어 팔았다는 신호입니다.

## 4. 트래픽이 적을 때의 대안

국내 초기 스타트업 대부분은 A/B 테스트를 돌릴 트래픽이 없습니다. 억지로 돌린 실험은 근거가 아니라 근거처럼 보이는 노이즈입니다.

| 방법 | 언제 | 주의 |
|---|---|---|
| 순차 롤아웃 | 좁은 세그먼트(지역·코호트·플랜)에 먼저 켜고 지표 확인 후 확대 | `leoreo`의 당근 원칙과 같은 도구. 비교군이 없어 외부 요인과 섞임 |
| 사전-사후 비교 | 변경 전 4주 vs 변경 후 4주 | 계절성·마케팅 캠페인 같은 동시 변화를 반드시 기록. 가장 흔한 착각의 원인 |
| 스위치백 | 시간대별로 A/B를 번갈아 적용 | 공급-수요 매칭처럼 사용자 단위 분리가 불가능한 경우 |
| 질적 검증 5~10명 | 새 흐름이 이해되는지, 어디서 막히는지 | 전환율 숫자는 못 얻지만 "왜"를 얻습니다 |
| 페인티드 도어 | 기능을 만들기 전 버튼만 두고 클릭률 측정 | `leoreo` 검증 사다리 2단계. 클릭 후 안내 문구를 정직하게 |

숫자가 부족할 때는 **"실험했다"고 말하지 않는 게 정직한 출력**입니다. 관찰했다고 말하고 불확실성을 함께 적습니다.

## 5. 실험 기록 템플릿

실험은 기록되지 않으면 조직에 쌓이지 않습니다. 진 실험이 더 중요합니다 — 같은 걸 두 번 시도하는 걸 막아줍니다.

```
| 항목 | 내용 |
|---|---|
| 가설 | ___을 ___로 바꾸면 ___가 ___만큼 좋아진다. 왜냐하면 ___ |
| 목표 지표 | (하나만) |
| 가드레일 | |
| MDE / 필요 표본 / 예상 기간 | |
| 시작일 · 종료일 | (시작 전에 확정) |
| 결과 | 목표 지표 변화, 가드레일 변화 |
| 판정 | 적용 / 폐기 / 재실험 |
| 배운 것 | 다음 실험에 넘길 한 문장 |
```

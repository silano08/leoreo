# AI 원가 부록 — 절감 기법과 유닛 이코노믹스

> 모델 단가·할인 정책은 매우 자주 바뀝니다. 아래 절감폭은 2025~2026년 공개 자료와 사례 기준이며, 적용 직전에 해당 제공자의 공식 가격표로 재확인합니다.

## 1. 왜 AI 제품은 마진이 다른가

전통 SaaS는 사용자가 한 명 늘어도 한계비용이 거의 0입니다. AI 기능이 붙으면 **모든 요청이 직접 비용**을 만듭니다. 사용자가 많이 쓸수록 원가가 같이 늘어서, 정액제와 결합하면 헤비 유저가 마진을 갉아먹습니다.

- 총마진: 전통 SaaS 75~85% vs AI 제품 50~60% (2026년 조사 평균 약 52%)
- 추론 비용이 매출의 4~9% 수준으로 공시되기 시작했고, 제품이 성숙하며 총지출에서 차지하는 비중도 오르는 추세입니다.

여기서 나오는 실무 결론이 둘입니다. **순수 정액제는 AI 제품에서 위험**하고(`leoreo-model` 참조), **원가 절감이 곧 마진 개선**이라 개발자가 직접 손댈 수 있는 지렛대가 큽니다.

## 2. 절감 기법별 상세

### 프롬프트 캐싱 — 제일 먼저 할 것
반복되는 앞부분(시스템 프롬프트, 문서, 예시)을 캐시해 두고 재사용합니다. 캐시된 구간은 주요 API에서 큰 폭(최대 ~90%) 할인됩니다.
- **적용 조건**: 요청마다 앞부분이 동일해야 합니다. 프롬프트를 조립할 때 **고정 부분을 앞에, 변하는 부분을 뒤에** 두도록 순서를 바꾸는 것만으로 적중률이 크게 오릅니다.
- **정확도 리스크 0.** 같은 내용을 같은 모델에 보내는 것이라 출력이 달라지지 않습니다.
- **함정**: 캐시 유효시간이 있습니다. 트래픽이 뜸하면 적중률이 낮아 효과가 줄어듭니다. 적중률을 로그로 남겨 실제 절감을 확인합니다.

### 모델 라우팅
쉬운 요청은 작고 싼 모델로, 어려운 것만 큰 모델로 보냅니다. 상당수 제품에서 요청의 대부분이 작은 모델로 충분합니다.
- **난이도 분류 방법**: 규칙 기반(입력 길이·기능 종류), 작은 모델이 먼저 시도하고 확신이 낮으면 승격, 또는 별도 분류기.
- **함정**: 승격 비율을 재지 않으면 총원가가 오히려 오릅니다. 작은 모델 실패 → 큰 모델 재시도는 **두 번 값을 냅니다.** `cost-per-successful-output`으로 판정해야 하는 대표 사례입니다.
- 반드시 평가 세트로 사전·사후 정답률을 비교합니다.

### 배치 처리
즉시 응답이 필요 없는 작업(야간 요약, 대량 분류, 색인)은 배치 API로 보내면 약 50% 싸집니다.
- **적용 조건**: 지연(수 분~수 시간)을 사용자가 감내할 수 있는 작업.
- 실시간 경로와 배치 경로를 아키텍처에서 분리해 두면 나중에 옮기기 쉽습니다.

### 컨텍스트 압축
대화 이력이나 문서를 통째로 넣지 않고, 요약하거나 검색으로 필요한 부분만 넣습니다.
- 긴 대화는 오래된 부분을 요약본으로 대체합니다. 문서는 전체 대신 관련 구간만 검색해 넣습니다.
- **함정**: 필요한 맥락이 빠지면 품질이 떨어집니다. 압축률과 정답률을 같이 재고, 압축 실패 시 원본으로 되돌리는 경로를 둡니다.

### 출력 길이 제어
출력 토큰이 입력 토큰보다 비쌉니다. 자유 서술 대신 구조화된 출력을 요구하고, 최대 토큰을 제한하고, "간결하게"를 프롬프트에 넣습니다. 리스크가 낮고 즉시 효과가 납니다.

### 셀프호스팅·양자화 — 마지막
GPU 고정비, 운영 인건비, 가용성 책임이 전부 우리 것이 됩니다.
- **손익 판단**: (관리형 API 월 지출) vs (GPU 인스턴스 월 비용 + 운영에 드는 사람 시간 × fully-loaded 시급). 후자에 사람 값을 빼먹는 계산이 가장 흔한 오류입니다.
- 물량이 크고 안정적이며, 모델을 자주 바꾸지 않을 때만 유리합니다.

## 3. 원가를 어떻게 재는가

절감 전에 계측이 먼저입니다. 최소한 아래를 요청 단위로 남깁니다.

| 필드 | 왜 |
|---|---|
| 기능(feature) | 어느 기능이 돈을 먹는지 |
| 고객 ID 또는 등급 | 코호트별 마진, 적자 고객 발견 |
| 모델명 | 라우팅 효과 측정 |
| 입력·출력 토큰 수, 캐시 적중 토큰 수 | 실제 청구액 재구성 |
| 성공 여부, 재시도 횟수 | `cost-per-successful-output` 계산의 분모 |
| 지연시간 | 절감이 사용자 경험을 해쳤는지 |

이 로그로 계산하는 핵심 지표는 셋입니다. **요청당 원가**, **고객당 월 원가**, **성공 결과당 원가**. 세 번째가 의사결정용이고 앞의 둘은 진단용입니다.

## 4. 유닛 이코노믹스에 미치는 영향

- **LTV 계산에 총마진을 넣습니다.** `LTV = ARPU × 총마진% × 평균 수명`. 마진을 빼고 계산한 LTV:CAC는 실제보다 좋아 보입니다. AI 제품에서 마진이 52%라면 LTV는 매출 기준의 절반입니다.
- **CAC 회수기간도 마진 반영입니다.** `CAC ÷ (월 ARPU × 총마진%)`. 마진이 낮으면 같은 CAC라도 회수가 훨씬 늦어집니다. 이것이 "AI 제품은 회수기간 계산이 달라진다"는 말의 실체입니다.
- **헤비 유저 꼬리를 확인합니다.** 상위 5% 사용자가 원가의 절반 이상을 쓰는 분포가 흔합니다. 평균만 보면 안 보입니다. 이 꼬리가 두꺼우면 정액제를 하이브리드(기본요금 + 오버리지)로 바꾸는 근거가 됩니다 — `leoreo-model`로 넘깁니다.
- **무료 플랜 원가에 상한을 둡니다.** freemium에서 무료 사용자 원가가 유료 전환 기대값을 넘으면 성장할수록 손해입니다. 무료 티어에 사용량 한도를 거는 것이 기능 제한보다 직접적입니다.

## 5. 절감 작업 우선순위 판단

원가 절감도 `leoreo` 투자 게이트를 통과해야 합니다.

```
| 항목 | 내용 |
|---|---|
| 현재 월 원가 | 해당 항목이 실제로 나가는 금액 |
| 예상 절감률 | 위 기법 표 기준 + 우리 상황 보정 |
| 연 절감액 | 월 절감액 × 12 |
| 개발 비용 | 소요 인일 × fully-loaded 시급 (+ 평가·검증 시간) |
| 품질 리스크 | 없음 / 낮음 / 중간 / 높음 + 검증 방법 |
| 판정 | 연 절감액 < 개발 비용이면 하지 않습니다 |
```

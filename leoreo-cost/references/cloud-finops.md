# 클라우드 FinOps 부록 — 태깅과 낭비 점검

> 서비스명·할인 제도는 2025~2026년 기준이며 변동 가능합니다. 적용 전 각 클라우드 콘솔의 최신 요금 문서로 확인합니다.

## 1. 태깅 규칙 — 가장 먼저

태그가 없으면 청구서는 "총액" 하나입니다. 무엇을 깎을지 알 수 없습니다. 리소스를 만들 때 강제하고, 나중에 붙이려 하지 않습니다.

| 태그 | 값 예시 | 쓰임 |
|---|---|---|
| `service` | `api`, `worker`, `db` | 어느 컴포넌트가 먹는지 |
| `env` | `prod`, `staging`, `dev` | 비프로덕션 낭비 발견 |
| `feature` | `search`, `ai-summary` | 기능 단위 ROI 계산 (`leoreo` 돈-체크와 연결) |
| `owner` | 팀·담당자 | 물어볼 사람 |
| `tenant` 또는 고객 등급 | `enterprise`, `free` | 코호트별 마진 |

인프라 코드(Terraform 등)를 쓴다면 태그 없는 리소스 생성을 정책으로 막습니다. 수동 생성 리소스가 낭비의 주범입니다.

## 2. 낭비 점검 체크리스트

분기에 한 번 훑습니다. 대부분 여기서 나옵니다.

**컴퓨트**
- [ ] 개발·스테이징 환경이 밤과 주말에도 떠 있는가 — 업무시간 외 자동 정지로 60~70% 절감
- [ ] 인스턴스 스펙이 실제 사용률 대비 과대한가 (CPU 평균 10% 미만이면 축소 후보)
- [ ] 상시 부하가 확실한 워크로드에 예약·약정 할인을 적용했는가
- [ ] 중단돼도 되는 배치 작업에 스팟·저비용 인스턴스를 쓰는가

**스토리지**
- [ ] 인스턴스에 붙어 있지 않은 디스크가 남아 있는가
- [ ] 오래된 스냅샷·이미지가 쌓여 있는가 (수명주기 정책으로 자동 삭제)
- [ ] 접근이 드문 데이터가 비싼 스토리지 등급에 있는가

**네트워크**
- [ ] 리전·가용영역 간 트래픽이 불필요하게 발생하는가
- [ ] 아웃바운드 트래픽에 CDN·캐시를 안 걸어 원본이 그대로 나가는가 (국내 서비스에서 가장 흔한 큰 항목)

**로그·모니터링**
- [ ] 로그 보관 기간이 필요 이상으로 긴가 (규제 요구가 없다면 30~90일)
- [ ] 디버그 레벨 로그가 프로덕션에서 켜져 있는가
- [ ] 모니터링 도구의 커스텀 메트릭·카디널리티가 과한가 — 청구서가 조용히 커지는 대표 항목

**외부 SaaS·API**
- [ ] 안 쓰는 좌석에 계속 요금이 나가는가 (분기마다 좌석 정리)
- [ ] 중복 기능 도구를 둘 이상 쓰는가
- [ ] 연간 계약 할인을 검토했는가 (해지 위험이 없는 도구만)

## 3. 예측을 개발 프로세스에 심기

- **PR에 비용 추정을 붙입니다.** 인프라 코드 변경분의 월 증분 비용을 자동으로 계산해 코멘트로 남기면(Infracost류), 리뷰 단계에서 "이거 월 얼마 늘어나는데 괜찮나"가 논의됩니다. 배포 후 청구서를 보고 아는 것보다 훨씬 쌉니다.
- **예산 알림을 3단계로 켭니다.** 월 예산의 50% / 80% / 100% 지점. 100%에서만 알리면 이미 늦습니다.
- **월 1회 비용 리뷰를 짧게 정례화합니다.** 전월 대비 가장 많이 늘어난 항목 3개만 봅니다. 원인이 설명되지 않는 증가가 조사 대상입니다.
- `leoreo` 돈-체크 테이블의 "인프라 증분 ₩/월" 칸을 이 추정치가 채웁니다. 기능 착수 승인 시 필수 입력입니다.

## 4. 국내 환경 참고

- **NCP(네이버클라우드)·KT클라우드·카카오클라우드**: 공공·금융 요건(망분리, 국내 리전, CSAP 인증) 때문에 선택되는 경우가 많습니다. 이때는 비용보다 요건이 선택 이유이므로, 절감은 인스턴스 스펙·스토리지 등급 조정 쪽에서 찾습니다.
- **트래픽 비용**: 국내 클라우드는 아웃바운드 트래픽 단가 구조가 해외와 다릅니다. CDN을 별도 계약하는 게 유리한 구간이 있으니 실사용량으로 비교합니다.
- **공공·대기업 납품**이 있다면 온프레미스/VPC 배포 요구가 따라옵니다. 그 원가는 클라우드 절감과 별개로 잡고, 딜 금액에 반영되는지 확인합니다 — `leoreo-b2b`에서 다룹니다.
- **정부지원금으로 받은 클라우드 크레딧**은 소진 후 실비 전환 시점을 달력에 표시해 둡니다. 크레딧이 끝나는 달에 갑자기 적자가 되는 패턴이 흔합니다.

## 5. 사람 원가

인프라보다 큰 원가는 대개 사람입니다. `leoreo` 부록의 기준을 그대로 씁니다.

- fully-loaded 비용 = 연봉의 **1.25~2배** ÷ 연 근무시간 (복지·세금·장비·채용비 포함)
- 절감 작업의 손익 계산에 반드시 이 값을 넣습니다. 월 3만 원 항목을 이틀 걸려 최적화하면 손해입니다.
- 반복 운영 업무를 자동화하는 것도 비용 절감입니다. 다만 같은 계산을 적용합니다 — 연간 절약되는 사람 시간 × fully-loaded 시급 vs 자동화 개발 비용.

## 출처

FinOps Foundation(Inform-Optimize-Operate 프레임워크), AWS·GCP 비용 최적화 문서(Well-Architected Cost Optimization), Infracost(코드 단계 비용 추정), 네이버클라우드·KT클라우드 요금 안내, `leoreo` 부록 `global-frameworks.md`(fully-loaded 인건비 기준). 요금 체계와 인증 요건은 2025~2026년 기준이며 변동 가능합니다.
